# 选题调研与产品假设

调研日期：2026-11-16。以下是公开项目和文档的观察，不是用户访谈、市场规模测算或增长承诺。星数会变化，因此不作为长期定位依据。

## 看到了哪些信号

1. [Agent Skills 格式](https://agentskills.io/specification)包含入口文档、脚本、参考资料与资源，审查范围天然超过单个 Markdown 文件。
2. [Vercel Skills](https://github.com/vercel-labs/skills)已经覆盖安装与更新。[锁文件一致性讨论 #2560](https://github.com/vercel-labs/skills/issues/2560)展示了安装状态、快照与更新之间的工程复杂度；部分问题后续已修复，不能把旧问题全部当作现存缺陷。
3. [NVIDIA SkillSpector](https://github.com/NVIDIA/skillspector)和 [Snyk Agent Scan](https://github.com/snyk/agent-scan)说明 Skill 安全分析已有成熟参与者。再做一套宽泛规则扫描器，差异化有限。
4. [SkilLock](https://github.com/skills-lock/skil-lock)与本项目最接近，已有能力差异、基线和审批工作流。它的文档也明确了跨文件引用建模的边界。因此本项目定位为引用链驱动的更新审查，并把可携带、可阅读的报告作为首要体验。

这些是需求存在的间接证据，不足以证明用户愿意采用 SkillDiff。项目尚未经过真实用户验证。

## 为什么选这个切口

- 目标用户清楚：维护 Skill 仓库的人、给团队分发 Skills 的开发者、审查上游更新的人。
- 痛点可以演示：入口文件不变，深层脚本变化，报告立即显示引用路径和新增证据。
- 采用成本低：无服务端、无模型费用、无账号、零运行时依赖；一分钟运行示例。
- 可以融入现有流程：本地审查、JSON 工具链、Markdown CI 摘要、HTML 附件。
- 边界可以验证：哈希、路径、行号、引用边都可由自动化测试验证；不靠无法复现的“AI 安全评分”。

## 首版差异化与未实现项

已实现：完整文件变化、静态引用图、前后引用路径、离线 HTML 报告、便携快照、CI 退出策略。

未实现：批量仓库发现、自动下载上游、实时执行观测、完整 YAML/代码语法分析、MCP 工具接口、公开数据集上的检测评估、经过验证的团队审批系统。没有宣称这些能力已经存在。

## 接下来用什么证据决定是否继续

1. 邀请 5 位真实 Skill 维护者对自己的更新做一次审查，记录操作是否成功、是否发现有价值的变化。
2. 收集至少 20 组可公开、可再分发的真实前后版本；标注引用解析漏报和误报，不发布未经许可的私有内容。
3. 观察维护者是否主动重复使用、是否愿意加入 CI，比单纯 star 数更能说明留存。
4. 根据反馈优先解决安装障碍和引用误判，再决定是否做批量扫描、Git ref 输入或 MCP。
